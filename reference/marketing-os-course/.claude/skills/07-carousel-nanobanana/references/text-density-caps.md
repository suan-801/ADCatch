# 슬라이드 텍스트 자수 캡 (★ 자동 검수 룰)

> 본 파일은 07-carousel-nanobanana 스킬이 슬라이드별 텍스트를 도출한 직후 **자동 자수 캡 검수**에 사용한다. 캡 초과 시 토큰 단위로 압축. 카드뉴스는 스크롤 정지·정보 흡수가 핵심이라 자수 캡이 광고 5단 카피보다 더 엄격하다.

---

## 1. 슬라이드별 자수 캡 (한글 기준)

| 슬라이드 타입 | 헤드 | 본문 | 비고 |
|---|---|---|---|
| **Hook** | ≤8단어 / ≤15자 | ❌ (헤드만) | 매거진 커버 톤. 한 줄 풀블리드 |
| **본문** | ≤6단어 / ≤12자 | ≤30자 × 최대 2줄 | 1슬라이드 1메시지 |
| **CTA** | ≤6단어 / ≤12자 | ≤20자 × 1줄 | 화살표·아이콘으로 시각 보강 |

> ⚠️ 영문은 단어 기준(words), 한글은 글자 기준(chars). 혼용 시 더 짧은 쪽 적용.

---

## 2. 슬라이드별 텍스트 요소 수 캡

| 슬라이드 타입 | 텍스트 요소 수 | 비고 |
|---|---|---|
| Hook | 1~2개 (헤드 + 부제 선택) | 비주얼 임팩트 우선 |
| 본문 | 2~3개 (헤드 + 본문 + 캡션 선택) | 위계 명확히 |
| CTA | 1~2개 (CTA + 짧은 부연) | 시각 영역 가벼움 |

> 텍스트 요소 4개 이상 = 빽빽함. 슬라이드 2장으로 분할 권장.

---

## 3. 자동 압축 절차 (★ 07 스킬에서 자동)

NanoBanana 호출 직전, 슬라이드별 텍스트가 캡을 초과하면:

1. **수식어 제거** — "정말 / 너무 / 진짜" 부사 우선 삭제
2. **조사·어미 압축** — "~입니다 / ~해요" → "~다 / ~죠" 또는 명사 종결
3. **숫자 표기 변경** — "이십팔일" → "28일"
4. **그래도 초과면 → 2슬라이드 분할 제안** — 사용자 보고에 "{N장 카드 너무 빽빽 → N+1장 분할 권장"

---

## 4. 시안 전체 자수 균형 (★ 시퀀스 룰)

N장 시퀀스에서 각 슬라이드의 텍스트 양은 비슷해야 함 (한 장만 빽빽 ❌). 표준 분포:

| 슬라이드 | 자수 균형 (예시 5장) |
|---|---|
| 1장 (Hook) | 15자 |
| 2장 (본문 ①) | 30~50자 |
| 3장 (본문 ②) | 30~50자 |
| 4장 (본문 ③) | 30~50자 |
| 5장 (CTA) | 15자 |

> 본문 슬라이드 간 자수 격차 2배 이상 = 시각 리듬 깨짐. 가장 빽빽한 슬라이드 기준으로 다른 슬라이드 보강하지 말고, **빽빽한 슬라이드를 압축**.

---

## 5. NanoBanana 텍스트 렌더링 한계 (★ 호출 전 주의)

- **한글**: Nano Banana 가 한글 자모 깨짐·획 왜곡 가능성 ↑. 슬라이드 1장에 한글 30자 초과 시 정확도 ↓
- **영문**: 단어 단위로는 안정적. 단 폰트 위계는 프롬프트로 명시 필요
- **숫자·기호**: 안정적 (% · / : - 등)

호출 직전 한글 슬라이드 자수가 30자 초과면:
- 옵션 A — 텍스트를 더 압축 (위 § 3 절차)
- 옵션 B — `model_tier: "pro"` 사용 (정확도 ↑)
- 옵션 C — 배경만 생성 + 사용자가 Figma/포토샵으로 텍스트 합성 (Method 2, SKILL.md 참조)

---

## 6. 신규 룰 추가 시

사용자가 "Hook 6단어로", "본문 슬라이드 3줄까지" 같은 룰성 피드백을 주면:

1. 위 § 1·§ 2 표 갱신
2. SKILL.md 체크리스트에 반영 (필요 시)
3. 현재 작업 중인 시안은 v 증가하며 압축 적용
